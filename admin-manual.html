1. Introduction — The Administrator Role

Welcome, Administrator. You hold full control over the {{SCHOOL_NAME}} college management system — the same product described in the Student Manual, but seen here from the management side. Everything a student, coordinator, or assistant admin can do flows from what you configure in this panel.

What the Admin Can Do

  • Register, edit, and (when permitted) delete students; manage admission numbers and years
  • Create and order courses, upload lessons and study notes
  • Record attendance and chapel attendance; apply waivers
  • Enter grades, build exams and quizzes, manage the question bank
  • Record payments, set installments, manage balances and fee agreements with evidence
  • Control fee-gated learning and the content access gate at global, regional, center, and per-student levels
  • Run coverage, contacts, and finance reports and export PDFs
  • Graduate students and migrate them to alumni; generate letters, diplomas, and completion certificates with verification codes
  • Create assistant admins (per-tab toggles) and coordinators; control coordinator access
  • Configure all Settings (branding, academic, signatures, admission numbers, terms, protection, maintenance, WhatsApp/SMS/M-Pesa), run backups/restores, and review the audit log

Admin vs Assistant Admin vs Coordinator

  • Administrator (you): unrestricted access to every tab and setting, including delete, restore, and security settings.
  • Assistant Admin: sees only the tabs you toggle on for them. Can delete students only if you allow it; never sees password/security or restore functions unless granted.
  • Coordinator: limited to their own center(s)/region — attendance, coverage follow-up, contacts, and the fee-gate screen you enable for them.
Rule of thumb: if a destructive or money-related action is involved (delete student, revoke certificate, restore backup, change M-Pesa production keys), do it yourself as admin or supervise it directly.

How to Use This Manual

Each section below is a task recipe with numbered steps. Work top-to-bottom the first time (Settings → Students → Courses → Finance → Gates → Graduation), then use the Table of Contents for day-to-day reference.

2. Logging In, Logging Out & Session Expiry

Your Admin Credentials

Your admin account is created during setup. Your username is your phone number or the admin ID issued by the developer, and your password is set privately. Students log in with phone + admission number; you log in with your admin credentials — never share them.

Step-by-Step: How to Log In

Step 1: Open your browser and go to https://netfoundation.ke.
Step 2: On the login screen, type your admin Username (phone number / admin ID).
Step 3: Type your Password exactly — passwords are case-sensitive.
Step 4: Click "Sign In" (or press Enter).
Step 5: On first-ever login, read the Terms and Conditions pop-up, tick "I agree", and click "Accept".
Step 6: Confirm you land on the Admin Dashboard with the full sidebar (Students, Courses, Finance, Settings, etc.). If you see a limited sidebar, you logged in as assistant/coordinator — log out and retry with admin credentials.

How to Log Out

Step 1: Click your name / profile icon at the top-right corner.
Step 2: Click "Logout" / "Sign Out".
Step 3: On shared computers, close the browser tab after logout.

Session Expiry & Re-login After Deploys

Sessions expire for security. After every server deploy / update, all sessions are invalidated and you must log in again — this is normal, not an error.

Step 1: If you see "Session expired — please log in again" or are returned to the login screen, simply log in afresh.
Step 2: After a deploy announcement, tell assistants and coordinators to log out and log back in before reporting "system errors".
Step 3: If login loops persist, clear browser cache and cookies, then retry; if still stuck, check Settings → Maintenance to confirm maintenance mode is OFF.
Bookmark https://netfoundation.ke. Use Chrome or Edge (latest version) for admin work; avoid old browsers for PDF and certificate printing.

3. Dashboard — Command Center

The Dashboard is your first screen after login. It summarizes the whole college at a glance.

What You Will See

📊 Statistics Cards

Totals for students, courses, exams/quizzes, fees collected vs outstanding, and attendance alerts. Click any card to jump to that module.

📝 To-Do & Alerts

Pending items: overdue installments, low-attendance students, unresolved tickets, upcoming exams, and ungraded submissions.

📅 Upcoming Events

Exam dates, term deadlines, graduation dates, and maintenance windows you set in Settings.

📢 Notifications (Bell Icon)

System alerts, ticket updates, payment confirmations (including M-Pesa STK callbacks), and backup reminders. The red badge shows unread count.

Daily Admin Routine (Recommended)

Step 1: Log in and scan the stat cards — note new students, balances, and attendance reds.
Step 2: Open the bell icon and clear/action all unread notifications.
Step 3: Check To-Do: overdue fees → Finance; low coverage → Coverage screen; open tickets → Support.
Step 4: Use the left sidebar to jump to the module needing action (Students, Finance, Coverage, etc.).
Start every morning on the Dashboard. A 5-minute scan prevents most end-of-term surprises.

4. Students — Register, Edit & Delete

How to Register a New Student

Step 1: In the sidebar click "Students".
Step 2: Click "Add Student" / "Register".
Step 3: Fill personal details: full name, phone (becomes Username), email, date of birth, gender, photo (optional, used for ID card).
Step 4: Fill academic details: program of study, study center, region, intake/year — see Year field below.
Step 5: Confirm the Admission Number auto-generated from Settings → Admission Numbers format (e.g., NET/001/07-26/001). Edit only if you have a reason.
Step 6: Click "Save". The student account is created immediately; login password = admission number until changed.
Step 7: Give the student their username (phone) + password (admission number) and the portal URL.

How to Edit a Student (incl. Year Field + Auto-Calculate Checkbox)

Step 1: Go to Students, search by name / admission number / phone.
Step 2: Click "Edit" / the student row.
Step 3: Update any field (contacts, center, program, photo, password reset).
Step 4: For study year: locate the Year field. Either type the year manually (1, 2, 3…) OR tick "Auto-calculate" so the system derives Year from intake date and academic settings. If Auto-calculate is ON, the manual Year box is locked/ignored.
Step 5: Click "Save" / "Update" and verify the profile shows the correct Year.
Important: Year drives graduation eligibility, fee targets, and coverage expectations. Leave Auto-calculate ON unless you have a repeater, transfer, or special case — then untick it and set Year manually with a note in the record.

Delete Rules — Only Admin / Assistant

  • Only Administrator and Assistant Admin (if granted Students-tab delete permission) can delete students. Coordinators can never delete.
  • Deleting removes login access; linked payments, grades, and audit entries are retained/archived per protection settings — never delete to "fix" a fee balance; instead correct the payment record in Finance.
Step 1: Go to Students → search the student → click "Delete".
Step 2: Read the confirmation warning and type/confirm as prompted.
Step 3: Click "Confirm Delete". Check the audit log entry afterwards (section 16).
Prefer to deactivate/transfer rather than delete (e.g., move to alumni on graduation, or change center). Delete only duplicates or erroneous registrations.

5. Courses, Sequence Order & Lessons / Notes Upload

How to Create a Course

Step 1: Click "Courses" in the sidebar.
Step 2: Click "Add Course".
Step 3: Enter course code (e.g., BTH101), title, instructor, credit hours, description/objectives, and program/year assignment.
Step 4: Click "Save". The course appears in the course list and (if published) to enrolled students.

Sequence Order — Controlling the Learning Path

Courses and lessons inside a course follow a sequence order number. Students see them sorted ascending — set this deliberately.

Step 1: In Courses, open the course (or the course list order view).
Step 2: Find the Order / Sequence field on each course/lesson row.
Step 3: Number them 1, 2, 3… in teaching order (e.g., Foundation → Doctrine → Ministry Practice).
Step 4: Click "Save Order" / save each row. Reopen the student view to confirm the order is correct.
Important: Gaps or duplicate order numbers confuse students and break coverage % calculations. Always keep sequence contiguous (1,2,3…) after adding or removing lessons.

How to Add Lessons and Upload Notes

Step 1: Open the course → go to "Lessons" tab.
Step 2: Click "Add Lesson", enter lesson title, order number, and study text/notes content.
Step 3: To attach files: click "Upload" / "Choose File" — select PDF, slides, or documents (study notes). Optionally add a video link/URL.
Step 4: Click "Save Lesson". Repeat for each topic in order.
Step 5: Preview as student (or check student view) to confirm notes open/download and videos play.

Class Schedule Tab

Step 1: Inside the course, open the "Schedule" tab.
Step 2: Add date, time, venue or online meeting link per session.
Step 3: Click "Save". Schedules appear on student Dashboards and in My Hub Exams/Schedule views.

6. Attendance & Chapel

How to Record Class Attendance

Step 1: Click "Attendance" in the sidebar.
Step 2: Select center, course, and date/session.
Step 3: Tick Present/Absent per student (use "Mark all present" then untick absentees to save time).
Step 4: Click "Save Attendance".
Step 5: Verify percentages update: Green ≥70%, Orange 50–69%, Red <50%.

Chapel Attendance

Step 1: In Attendance, switch to the "Chapel" tab/type.
Step 2: Select date and center, mark present/absent as above, and click "Save".
Step 3: Chapel counts are tracked separately but may feed graduation and coverage reports — confirm with your academic settings.
Important: Minimum 70% attendance per course is required unless an attendance waiver is applied at graduation (see section 12). Correct errors promptly — instructors/coordinators should report mistakes to you rather than editing locked past sessions.

Correcting an Error

Step 1: Reopen the same center/course/date session.
Step 2: Fix the ticks and click "Update".
Step 3: If the session is locked, use the manual override / unlock per your protection settings, then re-save.

7. Grades, Exams, Quizzes & Question Bank

Grading Scale (System Default)

  • A (80–100%) — Excellent — 4.0
  • B (70–79%) — Good — 3.0
  • C (60–69%) — Satisfactory — 2.0
  • D (50–59%) — Pass — 1.0
  • F (Below 50%) — Fail — 0.0

How to Enter / Publish Grades

Step 1: Go to "Grades".
Step 2: Select course (and exam/quiz source). Enter scores out of 100 per student.
Step 3: Click "Save", then "Publish" so students see them under Grades/Transcript.
Step 4: Spot-check one student transcript for correct letter grade and GPA.

How to Create an Exam

Step 1: Click "Exams" → "Add Exam".
Step 2: Enter title, course, date, time, venue/mode (physical/online), duration, and total marks.
Step 3: Attach questions manually or pull from the Question Bank (below).
Step 4: Click "Publish". Students register via Exams/My Hub; registered lists feed your attendance and To-Do.
Step 5: To allow a retake: open the exam → student row → "Allow Retake" / approve their retake request.

How to Create a Quiz

Step 1: Open the course → "Quizzes" tab → "Add Quiz".
Step 2: Set title, time limit, attempts allowed, pass mark, and whether correct answers show after submit.
Step 3: Add questions (or import from Question Bank), set marks, and click "Save & Publish".
Step 4: Scores auto-grade (objective types) and flow to Grades; highest attempt is kept where retakes are allowed.

Question Bank

Step 1: Go to "Question Bank".
Step 2: Click "Add Question": choose type (multiple choice / true-false / short answer), course/topic, question text, options, correct answer, and marks.
Step 3: Tag by course/topic for reuse. Click "Save".
Step 4: When building an exam/quiz, click "Import from Bank", filter by course, tick questions, and confirm.
Build the bank first, then assemble exams/quizzes from it — far faster and more consistent than typing fresh questions each term.

8. Finance — Payments, Installments, Balances & M-Pesa STK

How to Record a Payment

Step 1: Click "Finance" in the sidebar.
Step 2: Search the student (name / admission / phone) and open their statement.
Step 3: Click "Record Payment".
Step 4: Enter date, amount, method (M-Pesa / bank / cash), receipt/reference number, and received-by note.
Step 5: Click "Save". Totals update: Total Fee, Total Paid, Balance = Total − Paid.
Step 6: Issue/share the receipt number with the student for their payment history.

Installments & Balances

Step 1: On the student finance record, open "Installments" / payment plan.
Step 2: Click "Add Installment": enter amount + due date per installment until they sum to the total fee.
Step 3: Save. Each installment shows Paid / Pending / Overdue automatically as payments arrive or dates pass.
Step 4: Monitor Balances on the Dashboard and Finance list: green = fully paid, orange = outstanding.
Important: Never take payments to personal numbers. Receipt numbers must be unique and traceable — bank/M-Pesa references go in the reference field.

Fee Agreements with Evidence

Step 1: On the student finance record, open "Fee Agreement".
Step 2: Enter agreed total, installment promises, and deadline; upload evidence (signed letter photo/PDF, screenshot, guarantor note) via Choose File.
Step 3: Click "Save Agreement". The agreement + evidence attach to the student file for audit and graduation checks.

M-Pesa STK Settings — Sandbox vs Production + Callback URL

STK push lets you send a payment prompt to a student's phone. Configure carefully — wrong mode loses real money or fails silently.

Step 1: Go to Settings → WhatsApp/SMS/M-Pesa (M-Pesa section).
Step 2: Choose Environment: Sandbox for testing (fake money, test keys) or Production for live payments (real Daraja credentials: Consumer Key/Secret, Shortcode, Passkey).
Step 3: Paste the Callback URL — the public HTTPS URL the system listens on for M-Pesa results (e.g., your Railway/production domain + callback path). It must be reachable from the internet or payments will stay "pending".
Step 4: Click "Save", then send a test STK (sandbox first, then a small live amount) and confirm the Finance record auto-updates on callback.
Step 5: Only switch to Production after sandbox callbacks succeed. Keep production keys secret — never screenshot them into tickets.
If STK stays "Sent" forever: check callback URL, confirm production vs sandbox keys match the mode, and verify server logs/audit for callback errors.

9. Fee-Gated Learning — Master Toggle, Targets & Scopes

Fee-gated learning locks lessons/quizzes when a student falls behind on fees, nudging payment without manual chasing.

Master Toggle, Weekly Target & Deadline

Step 1: Go to Fee Gate / Fee-Gated Learning screen.
Step 2: Flip the Master Toggle ON to enforce gating (OFF = everyone learns regardless of fees).
Step 3: Set the Weekly Target amount (minimum paid-per-week to stay unlocked).
Step 4: Set the Deadline date — after this, rules tighten (or full balance required, per your policy text).
Step 5: Click "Save".

Tabs & Scope (All / Selected / Except)

Step 1: On the same screen, use the Tabs (e.g., Overview / Rules / Students / Regions) to navigate.
Step 2: Set Scope: All students (blanket rule), Selected (only listed centers/regions/students), or Except (everyone except listed).
Step 3: Pick the centers/regions for Selected/Except and click "Save".

Per-Student Target / Exempt

Step 1: Search the student in the fee-gate student list.
Step 2: To customize: set a per-student target (different weekly amount) OR mark Exempt (never gated — e.g., scholarship, staff).
Step 3: Click "Save". Exempt shows a badge; custom target overrides the global weekly target for that student only.

Regional Mode

Step 1: Enable Regional Mode if different regions need different targets/deadlines.
Step 2: Per region, set its own weekly target + deadline, then save.
Important: Test gating with one center (Scope = Selected) before going All. Always pair gating with clear student communication (WhatsApp fee reminders) to avoid surprise lockouts.

10. Content Access Gate — Global, Region, Center & Student

The Content Access Gate controls whether learning content opens at all — independent of fees. Use it to stage releases (e.g., open Term 1 everywhere, lock Term 2 until launch).

Levels: Global / Per-Region / Per-Center / Per-Student

Step 1: Go to Content Access / Access Gate screen.
Step 2: Set the Global default first (applies to everyone unless overridden).
Step 3: Drill down: override by Region, then by Center within a region, then by Student for special cases. Lower levels beat upper levels.
Step 4: Click "Save" at each level and verify the effective status badge.

Modes: Auto / Locked / Unlocked + Reset

  • Auto — follows fee-gate + schedule rules automatically.
  • Locked — forces closed regardless of fees (e.g., pre-launch content).
  • Unlocked — forces open regardless of fees (e.g., grace period, exam revision week).
Step 1: Choose Auto / Locked / Unlocked at the level you are editing.
Step 2: To undo custom rules and fall back to the parent level: click "Reset" / "Reset to inherit".
Step 3: Confirm the effective badge returns to inherited/Auto.
Typical setup: Global = Auto, one pilot Center = Unlocked for trials, pre-release courses = Locked until launch day.

11. Coverage Screen & Reports

Using the Coverage Screen

Step 1: Click "Coverage" in the sidebar.
Step 2: Filter by region / center / course. Each row shows student, lessons completed vs total, and coverage %.
Step 3: Click a student row to see lesson-by-lesson ticks and missing items.
Step 4: Follow up low-coverage students via coordinator/WhatsApp; re-check after a week.

Manual Override Pills

Step 1: On the coverage row, find the pill (status badge, e.g., Behind / On-track / Complete / Overridden).
Step 2: Click the pill to cycle or open the "Manual Override" dialog.
Step 3: Choose override value + reason (e.g., "transfer credit — verified by admin"), then "Save". The pill shows overridden state and logs to audit.
Important: Overrides affect graduation eligibility. Use only with evidence; never override to hide non-attendance.

Reports: Coverage / Contacts / Center Finance / Region Finance PDFs

Step 1: Go to Reports (or the Export button inside Coverage/Finance screens).
Step 2: Choose report type: Coverage (completion %), Contacts (student phone/email lists per center/region), Center Finance (collected vs outstanding per center), or Region Finance (aggregated per region).
Step 3: Set filters (region/center/date range) and click "Generate".
Step 4: Click "Download PDF" / print via the browser print dialog. File and share with coordinators as needed.

12. Graduation & Alumni Migration

Graduation Requirements

  • Pass all required courses (grades ≥ pass mark per academic settings).
  • Meet minimum coverage % (lessons completed vs total, per program settings).
  • Meet attendance threshold (default 70%) OR hold an approved attendance waiver.
  • Clear fee balance OR hold an approved fee agreement (with evidence).

How to Apply an Attendance Waiver

Step 1: Open the student record → Graduation tab.
Step 2: Find "Attendance Waiver", tick it, enter reason + approver name.
Step 3: Click "Save". The eligibility check re-runs with attendance bypassed for that student.

Graduation List & Migrate to Alumni

Step 1: Click "Graduation" in the sidebar.
Step 2: Review the eligible list (auto-checked against requirements incl. coverage % and waiver).
Step 3: Tick graduates → click "Approve" if approval step is enabled.
Step 4: Click "Migrate to Alumni". Students move from active to alumni status: logins are retired/archived, records kept for transcripts and certificates.
Step 5: Verify under Alumni list; issue certificates next (section 13).
Run graduation in batches per center to keep ceremonies and certificate printing orderly.

13. Certificates & Documents

How to Generate Letters (with Letter Date)

Step 1: Go to "Certificates" / "Documents".
Step 2: Click "Generate Letter" (e.g., admission, recommendation, completion letter).
Step 3: Select student, letter template, and set the Letter Date (printed on the letter — backdate only with authorization).
Step 4: Preview, then "Generate PDF" and print/file.

Diploma / Completion PDF Templates with Field Positioning

Step 1: Go to Settings → Certificates (or Documents → Templates).
Step 2: Choose template: Diploma or Completion Certificate.
Step 3: Upload background artwork (seal/logo border) and drag/set field positions: name (X/Y), course, date, signatures, Doc ID box. Save positions.
Step 4: Print a test copy on plain paper, measure alignment, adjust X/Y, and re-test before using official blanks.
Step 5: Return to Documents → select graduate → "Generate Diploma / Completion PDF".

Doc ID / Verify Codes, Verify & Reprint

Step 1: Every generated document gets a unique Doc ID + Verify Code printed on it.
Step 2: To verify: open Verify screen, enter Doc ID + code, and confirm student/course/date match.
Step 3: To reprint: find the document record → "Reprint" (same Doc ID, logged as reprint — do not mint a new ID for the same award).

Duplicates & Revoked

Step 1: For a lost certificate: use "Issue Duplicate" — it links to the original, marks "DUPLICATE", and gets its own audit entry.
Step 2: To invalidate (fraud/error): open the document → "Revoke" + reason. Revoked codes fail verification with a "REVOKED" message.
Important: Only the admin issues or revokes diplomas. Never edit a generated PDF by hand — re-generate from the system so Doc ID and audit stay consistent.

14. Users & Roles — Assistants and Coordinators

How to Create an Assistant Admin (Per-Tab Toggles)

Step 1: Go to "Users".
Step 2: Click "Add User" → Role = "Assistant Admin". Enter name, phone (username), and temporary password.
Step 3: Set per-tab toggles: switch ON only the tabs they need (e.g., Students, Attendance, Finance-view). Leave Settings/Security, Backup/Restore, and Delete OFF unless required.
Step 4: Click "Save". Ask them to log in and change their password.
Step 5: To adjust later: Users → open assistant → flip toggles → Save. Changes apply on their next login/refresh.

How to Create a Coordinator (+ Fee-Gate Screen)

Step 1: Go to "Users" → "Add User" → Role = "Coordinator".
Step 2: Assign their center(s) and region. They only see data for those assignments.
Step 3: If they need fee follow-up: enable their fee-gate screen access (per coordinator-access settings) so they see targets/balances for their centers without full Finance control.
Step 4: Click "Save" and share login + scope ("you cover Center X, Region Y").
Important: Review Users quarterly. Disable accounts of departed staff immediately (Users → Deactivate) rather than deleting, so audit history stays intact.

16. Backup / Restore & Audit Log

How to Take a Backup

Step 1: Go to Backup / Settings → Backup.
Step 2: Click "Create Backup Now". Wait for the success message + file entry (stored under server-data-backups / System backups).
Step 3: Download a copy to your computer / external drive for off-server safekeeping.
Back up before every: term rollover, graduation migration, bulk import, settings overhaul, and deploy.

How to Restore

Step 1: Go to Backup → Restore.
Step 2: Select the backup file (date-stamped) to restore from.
Step 3: Read the warning (restore overwrites current data), confirm, and click "Restore".
Step 4: Log out/in, verify students, finance, and certificates, then take a fresh post-restore backup.
Important: Restore is admin-only and destructive. Never restore over live data without a current backup taken first.

Audit Log

Step 1: Go to Audit Log.
Step 2: Filter by user, date, or action (login, payment, grade change, override, delete, restore, revoke).
Step 3: Click an entry for before/after details. Export/print for board or dispute evidence as needed.

17. Troubleshooting — Common Problems

Admin Cannot Log In / Session Expired Loop

  1. Confirm Caps Lock is off and credentials are the admin ones (not a student admission number).
  2. If just deployed/updated: wait 1–2 minutes, then log in afresh — sessions are invalidated on deploy.
  3. Clear cache/cookies or try incognito; try a different browser.
  4. Check Settings → Maintenance is OFF (via another admin session if needed).
  5. If locked out fully, contact the developer with server access for a password reset.

Student Cannot Log In

  1. Verify username = phone number on file; password = admission number exactly (case-sensitive, slashes included).
  2. Check Students record for typos; reset password if needed.
  3. Confirm Terms acceptance screen is not blocking them on first login.
  4. Confirm Content Access Gate / fee gate is not being mistaken for a login failure (they log in fine but see locked content).

Page Blank / Won't Load / PDFs Fail

  1. Refresh (F5 / Ctrl+R); check internet; try another device/network.
  2. Update browser; disable aggressive ad-blockers for the portal domain.
  3. For PDF/certificate print issues: use Chrome/Edge, enable background graphics, set margins to None/Default as tested.
  4. If after a deploy: hard refresh (Ctrl+F5) to drop cached JS.

M-Pesa STK Never Confirms

  1. Confirm Sandbox vs Production mode matches the keys in use.
  2. Verify callback URL is public HTTPS and reachable; check server logs for callback hits.
  3. Confirm shortcode/passkey correct; re-save settings and retest with a small amount.
  4. Record cash/bank manually meanwhile so student balances stay correct.

Coverage % Looks Wrong / Graduation Blocked

  1. Check course/lesson sequence order for gaps/duplicates.
  2. Check per-student overrides and waivers (attendance waiver applied?).
  3. Check Content Access / Fee Gate locks that prevent lesson completion.
  4. Reopen Coverage row detail to find the exact missing lessons, then fix source data.

Need More Help?

Check the Audit Log for what changed, take a backup before fixing, then file a support ticket with screenshots, admission numbers, and timestamps — or contact the developer.
